# xhqing（个人主页仓库）· 项目专属硬规则

本文件由 pi 在 cwd 位于本仓库（或其 worktree）时自动追加进系统提示。**只写本项目特有的约定**；全局规则与 Kit 的身份来自仓库根的 `AGENTS.md` 软链接，这里不复述、也不覆盖。

## 这是什么

GitHub 个人主页仓库（github.com/xhqing/xhqing），对外展示的**团队名册**与个人介绍。内容只有两份 README——`README.md`（英文）+ `README_cn.md`（简体中文）——加上 `VERSION` 与 `CHANGELOG.md`。**没有源码、没有构建、没有测试**，产物就是这两份文档。

## 硬规则

1. **名册必须与全局注册表同批对齐。** 名册的权威来源是 `~/.pi/agent/docs/agents-registry.md` 的两张表（智能体命名注册表 + 子项目映射）。registry 里 Agent 增删 / 改名 / 迁机、子项目新增 / 删除 / 归属变更，本仓库两份 README 的名册表都必须在**同一批改动**里跟着变，不问、不等确认。收尾前跑差异检查，差异必须归零：

   ```bash
   python3 ~/.pi/agent/patch/roster-sync/roster-sync-check.py
   ```

   该脚本只比「名字集合」，**Host machine 列它不查**——宿主机归属变了要手工同步那一列。

2. **双语同步是内容改动的一部分。** 改任一版 README 的措辞、列举项、口径、数字，必须同批改另一版、语义对齐（中文版为权威方向，英文按英文习惯表达，不逐字直译）。不要问「要不要同步」。

3. **名册表是 HTML 表格，改动要护住结构。** 一个单元格里多条子项目用 `<br/>` 分隔，`<td>` / `<tr>` 必须成对闭合。新增子项目 = 在同一单元格里追加「`<br/>` + 链接 + 一句话描述」；不要重排整张表，也不要换成 Markdown 表格语法。

4. **描述语自己写。** 一句话说清「它是什么 / 解决什么问题」，不夸大、不写与仓库无关的内容、不泄露个人信息与凭证。私有仓库照常列进名册（旧的「私有默认留空」口径已作废）。

5. **徽章区只留 License / Version / Type 三枚。** 访问量徽章已于 2026-11-04 随集中式采集一起停用，**不要再加回**；也不要添加 stars / forks / last-commit 这类动态徽章。

6. **不写敏感信息。** 这是公开仓库：不写个人财务状况、账户号、真实联系方式、API key；描述语按公开可读的标准写。

## 验证与发布

- 本仓库**没有构建与测试**，验证方式就是上面的名册差异检查 + 肉眼核对两份 README 的表格结构与链接。
- 纯文档仓库：改动不 bump `VERSION`、不发 GitHub Release（除非用户明确要求）。
- 一切写操作走 worktree + 分支 + PR + CI（required check `validate`），不直推 main。
